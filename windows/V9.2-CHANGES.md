# YORU V9.2 (0.9.2)

Current sidebar timing is 250ms, as requested with Scroll.mp4. This supersedes the prior 100ms adjustment. Icon/text timing stays 180ms. Existing V9.2 title correction and V9.1 player/card changes remain.

## Recording and root cause

Inspected Scroll.mp4: 299 frames, 60fps, approximately 4.98 seconds, 1920x1080. It shows Home, Explore, Trending, My List and Continue Watching switches. Frames and indicator-position samples are retained under evidence/sidebar-recording.

The controller routed every NavItems SizeChanged and Loaded event through SyncSelection(false). The old target guard applied only when animate was true, so even a width-only notification cancelled the current clock and assigned its destination immediately. A reproduction during an active slide, without changing the destination Y, jumped from 0.641 to 396 DIPs (395.359 DIPs) and removed the animation. The corrected reproduction records zero jump and an active clock. Temporary empty selection also previously hid the marker immediately.

## Final changes

- Controls/SidebarMotion.cs: keeps the existing persistent indicator; ignores unchanged targets for both navigation and layout notifications. Loaded/SizeChanged now synchronize without forcing a snap. Only initial placement snaps; subsequent target changes replace the current transform animation from its displayed value. A transient empty selection preserves the marker and colors. Uses 250ms CubicEase EaseInOut, SnapshotAndReplace and one held transform clock; no frame loop, timer, layout animation, API request or animation await. Existing 180ms color transitions and OS animation preference remain.
- MainWindow.xaml: one NavSelection border behind the original items, with the same height, rounded corners, margins and purple accent. Explicit SidebarNavigation radio group covers all eight items across the divider. Icon/text share each button's animated foreground brush; item geometry is unchanged.
- MainWindow.xaml.cs: creates/disposes the visual helper and synchronizes after existing ShowPage navigation. Details retain the originating section's checked state instead of clearing all buttons. Featured title cap is rounded to two line heights plus safety padding.
- Themes/Dark.xaml: removes per-item selected backgrounds while retaining original padding, hover surfaces and focus outline.
- MainWindow.xaml / DesignDiagnostics.cs: featured titles use BlockLineHeight and CharacterEllipsis, so two full lines fit without clipping. Includes the reported Kaoru Hana wa Rin to Saku case, longer English and Arabic titles, four sizes in EN/AR, and badge/action bounds checks.
- V92Diagnostics.cs: width-only interruption reproduction, 56 ordered section pairs, rapid retarget continuity, repeated Loaded events, empty selection, details/back, shared colors, EN/AR and four sizes. Tests verify one visible marker and unchanged geometry.
- App.xaml.cs: --v92-checks entry point. Version/localization metadata remains 0.9.2 / Version 9.2. build.ps1 includes this document. README.md and VALIDATION.md describe the final behavior.

The backend, APIs, player/overlay/decoder options, startup cache, storage, original artwork and shared anime card design remain unchanged. No new physical monitor-FPS or general performance claim is made.
