# YORU V1.0 (1.0.0): player maximize respects the taskbar

Root cause: custom borderless maximize used a full-monitor client area plus a fixed 7-DIP content margin. On the measured 1920x1080 desktop with a 1920x1050 working area, the native player rectangle was -7,-7 to 1927,1087. Its video/control foreground window extended to y=1080, and the control surface to y=1058, overlapping the reserved taskbar strip. Logical frame-inset checks in the older diagnostics did not verify the actual native/overlay bounds.

- PlayerWindowBounds.cs (new): handles the sizing data from WM_GETMINMAXINFO, using MonitorFromWindow and GetMonitorInfo for the current monitor. Sets maximum position relative to that monitor and maximum size from rcWork. Native coordinate values remain native; no hardcoded taskbar height, primary-screen assumption or global DPI-mode change. Minimum/maximum tracking fields are left intact.
- PlayerWindow.cs: attaches a player-only HWND hook and removes it on close. The sizing message remains unhandled by this hook, allowing WPF to enforce its existing minimum/maximum resize tracking. Fullscreen bypasses the work-area adjustment, retaining its original full-monitor behavior. Removes the fixed 7-DIP maximized content margin; windowed borders/corners and all media/playback logic remain.
- V93Diagnostics.cs / App.xaml.cs: --v93-checks measures actual player, WPF frame, control surface and LibVLC foreground-window rectangles, checks native minimum-size tracking, custom/native maximize and caption double-click, exact normal restore, fullscreen and fullscreen-to-maximized restore. Sixty synthetic work-area cases cover four taskbar edges, three monitor origins and five native-pixel scales without modifying desktop settings.
- V91Diagnostics.cs: updates the former fixed-inset assertion to zero; the new V1.0 diagnostics verify real monitor work-area containment.
- YORU.Desktop.csproj / Localization/strings.json / V8Diagnostics.cs: version 1.0.0 / Version 1.0 and executable metadata expectation.
- build.ps1 / README.md / VALIDATION.md: separate package and checks.

Measured final maximize rectangle: 0,0 to 1920,1050, exactly the reported work area. Video/control foreground window: 0,48 to 1920,1050. Controls end at y=1028. Fullscreen still covers 0,0 to 1920,1080, and fullscreen exit restores the working-area rectangle.

No API, streaming resolver, video/audio decoder option, seek timing, player overlay, history storage, main UI, theme, poster geometry, sidebar animation or DPI manifest changes. Existing V9.2 source and package remain separate.

References used to confirm native behavior: [WM_GETMINMAXINFO](https://learn.microsoft.com/en-us/windows/win32/winmsg/wm-getminmaxinfo), [MonitorFromWindow](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-monitorfromwindow), [multiple-monitor positioning](https://learn.microsoft.com/en-us/windows/win32/gdi/positioning-objects-on-multiple-display-monitors).
