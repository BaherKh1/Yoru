# YORU Android V9.3 ? exact catalog return (90310)

The old code saved only a first-visible adapter index and restored it with pixel offset 0. That request could be superseded by another asynchronous feed rebuild. It also kept catalog pointing at the origin while in Details, then wrote the Details scroll index into that catalog session during navigation.

SaveViewport now captures a stable row key, first-visible index and exact signed pixel offset, accounting for top margins and fixed-header padding. Bookmarks are isolated by page/query/genre/sort and bounded to 32 contexts. Only a matching, committed adapter context is saved; catalog position is updated only while on a paged section.

Opening details retains the original CatalogSession. Back reuses that same object, including all loaded pages, ordering and paging state. A pending viewport restore survives newer UI rebuilds; after rows are committed it aligns the saved row before drawing. A pre-draw guard prevents an intermediate top-position frame. There is no scroll animation, fade or artificial delay for Details -> Explore. If window geometry/data changes, missing-row/boundary restoration clamps to a valid position rather than blocking drawing.

Automatic pagination is deferred after a restored return until the user scrolls, avoiding immediate redundant fetches near the old end position. User-triggered retry and later normal infinite scrolling remain available. Explicit Home/Explore bottom-tab taps still scroll to the top as requested; ordinary Back restores the bookmark.

Modified application source: MainActivity.cs, FeedAdapter.cs (committed context and row keys), new Yoru.Core/ViewportBookmarks.cs and package version code. Regression coverage is added in ViewportBookmarkChecks.cs/Program.cs. No streaming API/resolver, storage, poster dimensions, More navigation rules or selected reference-explore navbar styling changes.

Validation: Release build has zero warnings/errors; all 14 portable groups pass, including signed/positive offsets, moved/removed anchors, Arabic query/sort separation, bounded bookmarks and retained multi-page session data. Signature/package/ZIP/Windows/style checks are recorded under evidence/explore-restore-*. No connected Android device is available; native pre-draw positioning and real touch/navigation still require phone verification. Bookmarks apply within the existing activity/session, not a cold process restart.
